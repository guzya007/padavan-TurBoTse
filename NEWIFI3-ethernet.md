# NEWIFI3 D2: исправление Ethernet

## Причина

В рабочем дереве `padavan-4.4` используется два GMAC: LAN через
`eth2` / MT7530 P6, WAN через `eth3` / MT7530 P5. В TurBoTse
`board.mk` задавал `USE_SINGLE_MAC`, поэтому userspace ожидал
`eth2.1` и `eth2.2`. При этом общий switch-код в
`drivers/net/ethernet/raeth/mtk_esw/esw_common.h` по-прежнему
выбирает два CPU-порта и нетегированный LAN на P6. Дополнительно
`newifi3.dts` удалял свойства GMAC2, отключая его инициализацию.
Это рассогласование объясняет поднятый физический линк без DHCP
на проводных портах при работающем DHCP через Wi-Fi.

## Изменения

- В `trunk/configs/boards/NEWIFI3/board.mk` убран `USE_SINGLE_MAC`.
- В `trunk/configs/boards/NEWIFI3/kernel-4.4.x.config` явно включены
  `GE1_RGMII_FORCE_1000`, `RAETH_GMAC2`, `RAETH_BOTH_GMAC` и
  `GE2_INTERNAL_GMAC_P5`. `RAETH_GMAC2` необходим для зависимостей
  Kconfig TurBoTse: одного переноса `RAETH_BOTH_GMAC=y` недостаточно.
- В `trunk/linux-4.4.x/arch/mips/boot/dts/ralink/newifi3.dts` сохранены
  оба GMAC из `mt7621-raeth-gmac2.dtsi` в режиме `force-1000`.
- Нумерация внешних портов сохранена как в рабочей прошивке:
  WAN=P4, LAN1=P3, LAN2=P2, LAN3=P1, LAN4=P0.

Код общих драйверов, QDMA, настройки Wi-Fi, DHCP и набор пакетов
не изменены. Уже имевшиеся локальные настройки `RA_HW_NAT=m`
и `MACVLAN=y` сохранены.

## SPI NOR

Удалён лишний include `mt7621-spi-32m-layout.dtsi`: вместе с собственной
разметкой платы он создавал повторные разделы `Bootloader` и `Storage`,
а также два раздела на весь чип. Используется только явная разметка
TurBoTse из `newifi3.dts`, её границы не изменены:

| Раздел | Смещение | Размер |
| --- | --- | --- |
| Bootloader | `0x0000000` | `0x0030000` |
| Config | `0x0030000` | `0x0010000` |
| Factory | `0x0040000` | `0x0010000` |
| firmware | `0x0050000` | `0x17b0000` |
| Storage | `0x1800000` | `0x0800000` |
| 25Q256JVFQ | `0x0000000` | `0x2000000` |

Частота SPI 32 МГц и ранее наследовавшийся `m25p,fast-read` сохранены.

Разметка `padavan-4.4` с Storage на `0x1a00000` не переносилась:
для Ethernet это не требуется. Старый Storage из другой разметки
не следует восстанавливать поблочно. Bootloader и Factory стирать нельзя.

## Сборка и проверка на роутере

Сборка запускается штатным `custom.yml`, target `NEWIFI3`;
изменять workflow не требуется. Для первого теста оставьте разгон
выключенным. Если основной роутер использует `192.168.1.0/24`,
задайте в customization другой LAN, например `"lanip":"192.168.50.1"`.

После прошивки рекомендуется сбросить настройки через веб-интерфейс
и не восстанавливать старую конфигурацию до проверки. Через Wi-Fi/SSH:

```sh
brctl show
ifconfig eth2
ifconfig eth3
cat /proc/mtd
dmesg | grep -E 'GMAC[12]|GE[12]_RGMII_FORCE_1000|HW-TRAP'
```

В режиме роутера без IPTV/VLAN-фильтрации LAN-мост `br0` должен
содержать `eth2`, а WAN должен использовать `eth3`. В `/proc/mtd`
должен быть ровно один `Bootloader` и один `Storage`. Проверьте получение
DHCP на каждом из четырёх LAN-портов, DHCP на WAN от основного роутера,
выход в интернет и оба диапазона Wi-Fi.

## Выполненные проверки

- Device Tree обработан препроцессором и DTC из этого дерева: ошибок
  и предупреждений нет; режимы обоих GMAC совпадают с `padavan-4.4`.
- Проверены итоговые разделы DTB: уникальные имена, непрерывная
  основная разметка на 32 МиБ, неизменные явные смещения разделов.
- Штатный `configure` и `olddefconfig` проверены для обычного и
  Nano-профиля в отдельной временной директории. GMAC2/P5 остаются
  включены; новые предупреждения Kconfig не появились.
- Проверены итоговые userspace-макросы: LAN=`eth2`, WAN=`eth3`,
  switch CPU LAN=P6 без тега, CPU WAN=P5, H/NAT поддерживает GMAC2.
- Проверены синтаксис shell-блоков `custom.yml`, отсутствие дубликатов
  параметров ядра и `git diff --check`.

Для этих проверок собраны только хостовые утилиты конфигурации.
Прошивка и ядро локально не собирались. Проверки исходников и
конфигурации не заменяют испытание готового образа на устройстве.
